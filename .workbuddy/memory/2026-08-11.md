# 2026-08-11 工作日志

## core 模块 RequestWrapper OOM 修复
- 问题：原 `RequestWrapper` 构造时用 `StreamUtils.copyToByteArray(request.getInputStream())` 把整个请求体读进内存 `bytes`，无大小上限；而响应侧 `ResponseWrapper` 已有 1MB 上限，两侧不一致，大 JSON / raw binary（非 multipart）请求可 OOM。multipart 文件上传走 `FormRequestWrapper`，不触发此问题。
- 修复（已编译通过 `:core:compileJava --offline`）：在 `RequestWrapper` 增加 `MAX_REQUEST_BODY_SIZE = 1MB` 常量与 `requestBodyTruncated` 标记；构造时改用 `readBodyWithLimit()` 按 1MB 上限读取，超出部分标记截断并 `drainRemaining()` 继续消费输入流（保持 keep-alive 连接状态）但不缓存；`getRequestBodyLogString()` 在截断时追加 `[request body truncated, total size > 1MB ...]` 标记。行为与 `ResponseWrapper` 对齐（连真实请求体也截断回放给 Controller，与原响应截断一致）。
- 权衡：开启 debug 日志且请求 body > 1MB 时，Controller 实际收到的 body 也会被截断（与响应侧已有行为一致）；如需保留完整 body 给业务，需改架构（如落临时文件），当前未做。

## RequestWrapper 方案修订（用户三约束：日志上限4MB / 业务body必须完整 / 性能优先）
- 推翻上一版「连同回放一起截断」的做法：用户明确业务 body 完整是根本，性能优先。
- 最终方案（已编译通过）：`bytes` 仍用 `StreamUtils.copyToByteArray` **完整缓存**（单次读取，最快，Controller 回放 body 始终完整）；`MAX_REQUEST_BODY_SIZE = 4MB` 仅用于**日志截断**；`getRequestBodyLogString()` 用 `new String(bytes, 0, min(len,4MB), UTF_8)` 只取前 4MB 组装日志字符串，避免日志字符串 OOM；`requestBodyTruncated` 在构造时按 `bytes.length > 4MB` 标记，截断日志追加真实大小提示。删除上一版的 `readBodyWithLimit`/`drainRemaining`（不再需要 drain，性能更好）。
- 残余风险：极端大 body（> 剩余堆内存）仍会让 `bytes` 撑爆堆导致 OOM（与最初问题同源），但用户已明确优先业务完整+性能，故接受该取舍；若后续要兼顾内存上限且不损业务，需引入临时文件回放（>=4MB 落盘、<4MB 内存）。

## 构建配置调整（支持测试运行）
- `test/build.gradle` 增加 `test { useJUnitPlatform() }`：原默认走 JUnit4 运行器，无法运行 jupiter(@Test 来自 org.junit.jupiter.api) 测试，会报 InvalidTestClassError。
- 根 `build.gradle` 的 subprojects `JavaCompile` 增加 `sourceCompatibility/targetCompatibility = '1.8'`：本机只有 JDK17，默认产出 Java17 字节码(v61)，Spring Boot 2.3.7 自带 ASM 组件扫描读不了 → ClassReader IllegalArgumentException。本项目本就目标 Java8，故强制 Java8 字节码（Gradle 6.4.1 不支持 `options.release`，故用 source/targetCompatibility）。
- 构建环境坑：gradle daemon 会锁 build 目录，导致 clean/processResources 失败（Unable to delete / Failed to clean up stale outputs）。解决：`./gradlew --stop` + 手动删 build 目录 + 运行加 `--no-daemon`。

## RequestWrapper 代码审查优化（已应用，低风险）
- `getInputStream().isFinished()` 由 `return false` 改为 `return byteArrayInputStream.available() == 0;`（语义更准确）。
- `getParameter` 用三元表达式简化。
- `packageParameterMapAll` 遍历改用 `entrySet()`（避免 keySet + get 二次查找）。
- 修正构造器不准确的 `@throws IllegalArgumentException if the request is null` javadoc。
- 未改动各 contentType 业务分支逻辑（避免回归）。
